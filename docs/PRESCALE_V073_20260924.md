It compares raw ridge, standardized ridge, a training-fold constant, matched-use random routing and Flash. No final task outcomes enter fitting or selection. No hyperparameter sweep is scheduled.

## Repair package: at most 140 attempts

- The same 40 math development tasks × two samples, local L only: 80 calls. One concise stopping prompt; the original 8,192 ceiling and decoding settings remain.
- The same 20 pre-existing reading feedback tasks: one protected-contract Flash answer and one protected-contract retained L-plan→M-solve answer per task. At most 60 node calls (20 local, 40 Flash), producing 40 answers.
- Total: 120 answers, at most 100 L and 40 M calls. No H or D calls. CNY1 reference API cap; GPU separate. No automatic second prompt variant.
- The system template owns the final output contract. Generated workflow hints cannot edit it. Reading accepts a complete JSON object or one outer JSON fence; fields/types/unique keys/nonnegative sentence indices are checked. No extraction from arbitrary prose, answer guessing, or LLM repair.
- Prior responses are reused as controls; both old and new reading responses use the new deterministic parser, with legacy scores preserved in v072. Math uses the existing strict scorer and a separate audit of every nonliteral new answer. Responses are durable before scoring; raw labels remain unchanged by adjudication.

Math acceptance requires fewer truncations, no lower observed end-to-end quality, and no higher mean output tokens. Reading acceptance requires fewer pooled malformed answers, no increase in either candidate's malformed count, and no decrease in pooled observed F1. These are small-sample engineering gates, not non-inferiority or significance claims. Claude must also inspect new failure cases before approving follow-on search. A failed gate stops that upgrade; it does not trigger repeated experiments.

## Conditional MBPP search comparison: at most 870 attempts

Proceed only after the reading repair passes its numeric gate and a signed review records no unresolved systematic regression. Failure of the math-only stopping variant is recorded independently; that prompt is never used for MBPP.

The earlier 880-call ceiling now explicitly includes same-protocol initialization and screening controls:

- Shared initialization: six seed workflows × ten fixed development feedback tasks, at most 90 node calls. All seeds are reevaluated with the v073 protected contract rather than silently reusing a different prompt protocol.
- Shared screening controls: L/M/H × the same 20 screening tasks, 60 calls.
- Four runs: two search seeds × pure-elite / mixed exploration, **180 attempts per run**, including proposals, candidate execution and winner screening. Total ≤150 + 4×180 = **870**.
- Each run has at most five candidate slots, two proposal attempts per slot, ten feedback tasks per valid candidate and one 20-task screened winner. Reserve up to 60 calls for winner screening. Remaining budget can prevent filling all slots; no top-up to reach five or replace duplicates.
- Both strategies have the same attempt, token, currency, graph and screening limits. Shared work is reported separately, and actual spend need not be equal. Per run: CNY5/USD0.25 reference caps. Shared initialization/control phase: CNY3, no D calls. Combined with repair: at most CNY24 + USD1, excluding GPU; these are safety caps, not predicted invoices.
- Mixed slot schedule: elite, parentless restart, elite, historical nonelite, elite. Empty nonelite pools record an explicit elite fallback. Restart uses no parent graph. Parent policies are deterministic per search seed; the API proposer does not support deterministic seeds.
- Explicit operations model-swap, prompt-edit, add, deletion/merge and rewiring are applied by code, preserving all unmentioned parent fields. The before/after graph is recorded. Duplicate or invalid proposals consume attempts. Legal branching is allowed, not required merely to increase diversity.
- All evaluated candidates remain in the exploration history; occupied niches retain their empirical elite for parent selection. Candidate ranking remains the documented quality tolerance then API cost, without using screening results during search. This experiment isolates the bounded exploration policy; it does not yet implement a new marginal-portfolio search objective.
- The two strategies' winners are compared with same-protocol single-model controls on the same 20 tasks. These already-observed v072 development/screening tasks are engineering material, not fresh confirmation. Two seeds are a pilot. No new final evaluation is opened.

Automatic escalation, an upstream-node causal ablation, semantic feature sweeps, larger model selection and large-scale confirmation are outside this launch. End when the bounded package is complete, a gate fails, or a hard limit blocks completion.
