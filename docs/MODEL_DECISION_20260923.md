# 实验前决策：High 固定为 Qwen3.8 Max

2026-09-23。下一轮主执行池：本地 Qwen3.5-9B AWQ / Qwen3.7 Flash 固定快照 / Qwen3.8 Max 固定快照。DeepSeek Flash 保留外部单模型强基线和统一工作流提议器；执行、提议两部分用量分开。此决策冻结实验设计，不宣称主程序已经完成迁移。

## 为什么采用 Max

研究目标是检验本地算力、低价云端与昂贵云端并存时，工作流搜索与请求路由是否发现有用的质量—成本权衡。Max 延续此前声明的配置，也具备固定日期模型身份，适合这一主场景。

这不是“Max 已被证明更强”的决定。v071 中 Max 与 DeepSeek 均为 41/42，错误题不同；Max 比 Qwen Flash 净多答对两题，样本不足以确认稳定优势。DeepSeek 的本轮延迟更短、费用有竞争力，因此仅依据现有服务表现，没有证据说换成 Max 是更好的生产部署。

同一 Qwen 家族便于描述模型池，但版本、训练、量化和服务条件仍不同，不构成仅控制参数规模的实验。模型价格差只能定义研究场景，不能制造方法贡献。

## 主结果必须回答的问题

1. 每个任务域分别报告 L、M、H、DeepSeek 单模型结果，保留没有 Max 优势的任务。
2. 比较固定工作流与搜索工作流；相同预算下比较单精英与多生态位，才可讨论搜索和档案的价值。
3. 比较 L/H、M/H 与 L/M/H、简单级联和匹配模型使用比例的随机路由，验证第三档及学习路由的增量。
4. 同时报告质量、API 用量、GPU 时间和延迟；将搜索与校准成本计入摊销分析。
5. DeepSeek 为外部强对照；后续将 H 替换为 DeepSeek 的独立迁移实验可检验方法对模型池的依赖，不混入当前冻结主配置。

若跨域开发证据仍显示 Max 没有条件质量收益，应如实降低三档必要性的主张，调整后续资源投入；不能挑选终评样本来证明预期排序。预算与终评边界沿用 [v072 规划](MULTIDOMAIN_V072_EXPERIMENT_PLAN_20260923.md)。
