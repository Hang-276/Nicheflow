# 下一轮修改建议：本地小模型与云端模型混合部署

2026-09-23。本文是结果复核与修改建议，尚未修改实验代码、模型配置、评分或启动付费调用。

**后续更新：** 本文下方保留v070完成前的讨论，Qwen2.5部署及待选模型等描述是历史状态。现已完成本地Qwen3.5-9B AWQ与云端模型对照，并发现旧评分器大量漏判。最新优先级、三档建议、19项问题与对应验证，以 [问题—修改—验证清单](ISSUE_VALIDATION_MATRIX_20260923.md) 为准；旧v052/v060数值需在新评分口径下离线复核。格式保真策略已在v051配置启用，并非仍是未部署草案。

## 部署意图

用户明确：三档按模型能力与成本区分；其中可部署的小参数模型放在租用的 GPU 服务器，其余模型通过 API 调用。本地/云端是部署属性，不应直接等同于强弱属性。

上一条建议中的 Qwen3.8-Flash 是服务模型名，不能据此认定有同名可下载权重。若采用本地低成本档，应明确选择开放权重的 checkpoint。官方 Qwen3.8-27B 提供权重与部署说明，可以作为较大的本地候选，但尚未验证具体量化版本在现有单卡上的显存占用、速度和质量。也可选更小的开放权重模型做对照。不能把它们视为 Qwen3.8-Flash 的同款本地替代。

最近完成实验的环境记录为单卡 RTX 4090；这不是对当前服务器状态的实时检查。原环境使用 Transformers 4.47.1、Qwen2.5-7B-Instruct-AWQ、单路本地推理。换新架构需另建兼容环境、固定权重与量化配置，并测试真实输出预算下的显存和吞吐。

## 已复核证据

现有代码身份与 v060 冻结代码完全一致。再次读取原始请求确认下面的节点提示和输入边，未重新调用模型。

| v060，140题×2次采样 | 正确率 | 高峰美元/1000次单次作答 | 节点调用秒数之和/次 | 截断 |
|---|---:|---:|---:|---:|
| A 单次 Flash | 90.00% | 0.6259 | 2.21 | 12/280 |
| B 简洁 Flash | 88.21% | 0.4955 | 1.82 | 16/280 |
| C Flash规划→本地Qwen审阅→Flash最终 | 87.50% | 0.8175 | 18.20 | 11/280 |
| D Flash规划→Flash最终 | 90.71% | 0.8492 | 3.11 | 8/280 |

D−A=+0.71个百分点，事后配对95%区间[-1.07,+2.86]，增加35.7%费用，未证明更优。C−D=-3.21个百分点，原95%区间[-6.43,-0.36]，多重比较敏感性区间覆盖0；是负面信号，不是所有审阅有害的证明。B省20.8%费用，但没有证明质量非劣。

v052：Flash单模型89.8%；学习后三个路由点为86.4%、87.2%、82.6%，且费用与调用耗时均高于Flash。17个路由臂各自拟合29维模型，280次校准反馈分配到每臂10–21次。去掉已存分数中的探索宽度会使多数选择改变；这只证明选择敏感，未执行新答案，不证明均值路由一定更好。

两个单模型已有回答：317题都对、132题仅Flash对、4题仅Qwen对、47题都错。单模型回答的事后理想选择90.6%不能代表所有未来多节点工作流的上限；317题也只是节省API费用的潜在空间，不是部署时可直接识别的集合。

## 修改顺序

### P0：节点职责、模型适配、预算与目标

**1. 分开计划、计划审阅、答案审阅、最终求解的输入输出契约。**

- C的规划用户提示要求“不要解题，只给计划”，但公共task仍带最终boxed答案格式要求。
- C的计划审阅用户提示要求“只返回改进后的计划”，系统级Review&Revise却要求独立核验最终答案、无法证实错误时保留原boxed答案。这是职责不匹配；不能仅由此推断整个差异的因果占比。
- C最终节点只接收review输出，没有原始计划；最终提示是“使用改进后的计划，只返回最终答案”。这可能强化对上游的依赖。
- 建议为中间节点定义明确输出类型，最终答案格式仅强制作用于最终节点；计划审阅返回问题、证据及改动建议，不伪装成完整求解。最终节点可读取原计划与审阅意见，把它们当作待核验材料。保留原题独立求解作为对照。
- 原有Review&Revise已经写过“独立核验、非必要不改答案”，因此仅追加同一句提示不足以构成新修复。
- 有无审阅的机制实验共享预先冻结的上游计划，再对下游做独立重复采样。v060的C、D上游独立生成，不能把逐题差异完全归因于审阅。

代码位置：`nicheflow/graph.py::graph_messages`、`nicheflow/workflow_contracts.py::operator_instruction`、`configs/fixed_validation_v060.json`。

**2. 新模型适配需要实际生效的思考模式、节点预算和推理后端。**

- `MainAPI.generate`目前只对DeepSeek显式设置thinking；其他提供商没有传相应开关。本地chat template也没有显式配置思考开关。换入默认思考的新模型时，不能声称仍是同一非思考协议。
- 当前所有节点共用2048输出上限，节点仅可覆盖temperature。规划、核验、最终求解应可分别设置预算，记录实际生效参数和推理/答案消耗。
- 2048与更大预算、一次有限回退等，必须在新验证划分对全部预定题比较。保留2048基线，计入失败和重试调用的全部费用；不要从已发生截断的题中挑出有利子集宣称修复。
- v060共47次截断；B更简洁但截断更多。输出预算是需要测试的因素，不是已证实的唯一主因。
- 独立本地服务可统一接口、改善调度，但吞吐提升须测量；不要把并发执行多道题等同于单题更快。v060的279次Qwen审阅平均每次15.305秒，耗时瓶颈需要单独定位。不能仅因awq_ext缺失就认定性能原因。

代码位置：`nicheflow/main_models.py::MainAPI.generate`、`nicheflow_probe/backends.py::generate`、`nicheflow/runtime.py::execute`。

**3. 将质量—成本目标写成可检验条件，并统一主费用口径。**

- 当前选择分数为min(wq×UCBq,wc×UCBc)。v052中[0.25,0.75]的所有选择受质量项限制，[0.75,0.25]全部受成本奖励项限制，不能将系数直接解释为偏好百分比。
- 建议下一轮主目标采用“允许的质量损失不超过预先约定的δ时，最小化高峰API支出”；例如δ=1个百分点只能是待冻结的实验选择，不是已获保证。非劣性需要配对置信区间与足够样本，跨0不等于无损。
- 另一条质量提升目标应单独报告固定预算下的准确率；不以更贵但未显著增益的流程宣称成功。
- 当前学习成本读取accounted_usd（冻结费率按时段/缓存核算），报告另列高峰未缓存参照。这不是复算错误，但新的主优化目标若是高峰成本，应让搜索、候选筛选、路由与主报告统一使用该成本；实际支付估算单列。
- 保持用户既定口径：本地费用不加入API货币目标，本地推理耗时单列。可另设延迟约束，不将GPU租金擅自加入原目标。

代码位置：`nicheflow/router.py::choose`、`nicheflow/main_policy.py::total_reference_usd`、`nicheflow/main_models.py::api_charge`。

### P1：小候选池与部署路由

**4. 搜索档案与可部署候选池分开。**

- 搜索档案保留多样性与历史血缘；不能因全局均值不占优就删除可能有条件价值的候选。
- 部署池先由三档单模型与少量明确对照构成，建议3–5个；历史精英不会自动获得永久上线资格。
- 候选在开发数据生成，在独立筛选数据确认可贡献的质量/成本权衡或稳定子群优势；重复采样、报告配对差异，避免70题上偶然多对两题就把它视为最佳部署方案。
- 加入候选前分配基本校准预算。小验证集不宜立即用复杂高维共享模型替代；共享统计或降低维度都是需要对照的候选改法。

**5. 区分在线探索与冻结部署选择。**

- 现有冻结评测继续使用质量/成本UCB加成，但不更新反馈。这忠实执行原协议，不是评测泄漏；它可能持续偏向不确定候选。
- 保留原UCB作为对照；下一轮比较预先选定的均值策略和校准后的质量约束策略。保守质量下界并非现有小样本模型自动能保证，需单独校准。
- 在同一候选池、同一数据划分上，比较强模型常开、各单模型、同调用比例随机路由、简单学习路由与NicheFlow路由。随机对照还应给出真实费用，不能假定同调用比例即严格同费用。
- 本地模型可直接完成可提前识别的题；升级或核验根据可观测特征和校准信号触发，不能以gold答案决定，也不直接信任模型自报的高置信度。
- 固定DAG当前没有通用条件退出语义；如果要做级联，应把有界升级/停止作为明确执行策略，计入所有先前调用。不要用“接入三档”暗示已经实现动态级联。

### P2：搜索方向与研究对照

**6. 明确产生精简候选，减少只追求开发集质量的筛选偏向。**

- 合法提议43次中，33次插入节点、仅1次删除；允许删除不等于实际探索了删除。
- 建议先规定删除/合并、模型替换、提示调整、重连等提议类别及预算，设置专门精简轮；类别比例是待验证设计，不是根据当前测试最优倒推的参数。
- 加入单次调用、最多一次高价调用等成本受限候选作为对照，不先扩大12节点上限。
- 当前代理只预测开发集quality并筛掉一半候选，未直接优化质量—成本权衡。它可能过滤稍低准确率但很便宜的候选，下一轮比较成本分层保留或多目标筛选，并留少量未经代理筛选的随机评估以检查漏选；当前没有实测代理漏选率。
- 重启生成、历史非精英繁殖仍值得后续独立消融；本轮已有四代后代，不能把种子依赖认作已证实主因。

**7. 先用固定搜索/校准预算验证基本收益，再检验自适应调度。**

- 若同时调整模型、节点、路由、变异与调度，最终提升无法归因。
- 第一阶段完成模型与执行协议预检，固定模型版本、量化、思考模式、节点预算与成本口径。
- 第二阶段做小候选池单模型路由与受控节点对照；保留DeepSeek Flash基线。
- 第三阶段比较固定候选池与有搜索的候选池，在相同部署路由下观察搜索增益，再对探索策略/调度做消融。
- 报告搜索生成与验证开销、路由校准开销、终评开销和部署每题开销。若部署每题有节省，再计算额外学习支出的摊销规模，不把重复采样自动解释为部署必须双调用。
- 保留既有历史结果。已分析的MATH-500和v060可以作诊断/回归集；新的确认性结论需要未用于方案选择的独立数据，参数和主要比较在评测前冻结。多随机种子是最终稳定性验证，不能用加100轮替代。

## 对本轮的总体判断

当前结果共同指向候选节点价值、职责匹配、有限校准反馈和目标语义等问题。调整模型池可能扩大有用的质量—成本空间，但不会自动修好上述机制。最先应做的是节点契约和模型适配，再建立小候选池的可靠路由基线；随后才值得扩大完整NicheFlow搜索。

这些修改是待检验建议。未声称三档、独立核验、均值路由、增加预算、条件级联或新的本地后端已经带来收益。
