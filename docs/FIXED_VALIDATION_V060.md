## 四组与数据

| 组 | 固定流程 | 作用 |
|---|---|---|
| A_flash_original | 单 Flash，原解题提示 | 强基线 |
| B_flash_concise | 单 Flash，原提示增加简洁作答要求 | 区分输出冗长/截断与协作收益 |
| C_best_with_qwen | Flash 规划 → Qwen 审阅计划 → Flash 解题 | 原开发集最佳流程完整固定执行 |
| D_without_qwen | Flash 规划 → Flash 解题 | 仅删除 C 的 Qwen 节点并重连最终输入 |

C 的来源是第 30 轮保存状态中的开发集最佳工作流 `6e8752093f669ff4ab416e3dc3e58a439ec5316be984de17206dcd4f96eecbc9`，原开发集分数 64/70。选择不依据 MATH-500 测试成绩。

- 数据来自已固定版本的官方 MATH train。排除已有开发、校准、探针及 MATH-500 中出现的问题，使用与原协议相同的规范化问题哈希去重。
- 固定抽样种子 2026092206：7 学科 × 5 难度 × 每格 4 题，共 140 道新验证题。它是均衡分层的验证集，不把它当作与 MATH-500 同分布的最终测试集。
- 每题每组独立采样 2 次，共 1,120 次流程执行，最多 1,680 次 Flash 和 280 次 Qwen 调用。不跨组复用生成答案或规划输出。
- 保持原模型快照、评分、输出处理与 2,048 输出 token 上限。原默认温度 0.7；C 保留节点温度 0.7/0.3/0.5，D 保留 0.7/0.5。因此 C−A 包含提示、温度、拓扑等多项差异，不能单独归因为协作拓扑。
- 140 题在运行时均标为 evaluation，禁止用于本轮的搜索、路由学习或反馈更新。参考答案仅用于评分，不进入模型消息。

## 并发与资源

- 最多 8 个独立流程在途；全局最多 4 个 API 请求、1 个本地 Qwen 推理。一个流程内部仍遵循节点依赖顺序。
- 派发顺序事先确定，完成顺序由实际耗时决定。所有组使用同一并发规则。Flash 不保证 seed 可复现，两次响应全部保留，不择优。
- 单写者哈希链日志；调用开始、费用预留及结果写入加锁，网络请求期间释放日志锁。本地模型只接收一个请求，API 每次调用独立设置超时。
- API 硬上限 $10、调用硬上限 1,960、总墙钟上限 8 小时。$10 是上限而非预计支出；并发预算计算包括尚未返回请求的最坏费用。
- 费用未知时停止新请求，已在途请求收回并记录结果；不自动重试未知付费请求。断线不会自动重发，恢复必须核对原始日志。仍保留原连续三次流程异常停止规则；并发下按日志完成顺序判断，已经发出的请求可能继续返回。
- 依据上轮平均 Flash 2.09 秒、Qwen 14.60 秒粗估，串行约 2–3 小时；并行后约 1–1.5 小时，取决于本轮审阅输出长度。Qwen 最多 280 次对应约 68 分钟的历史均值工作量，是主要下界来源。8 小时是故障保护上限。

## 统计与费用口径

- 正确率取两次采样的平均，不是 pass@2。截断按原协议计 0，同时独立统计截断数。
- 同时报告两次采样各自的准确率、平均准确率、API 花费、本地推理秒数与流程各节点调用秒数之和。并行墙钟时间单列；节点调用时间之和不含排队，不作为独占资源时的延迟基准。
- 预先固定四个比较：B−A、C−A、C−B、C−D。按问题做配对 bootstrap，保留同题的两次响应一起抽样，10,000 次重采样，给出未做多重校正的探索性 95% 区间。
- 统一高峰未缓存参照价：Flash 输入 $0.30/百万 tokens，输出 $1.20/百万 tokens；另报回执 usage 按原冻结费率估计的实际费用，尚未逐笔核对服务商账单。本地货币成本依原约定为 0，耗时单列。
- 不能用本轮新验证集分数改写原 MATH-500 测评，也不能仅按最高点估计宣布某流程更强。验证结果用于决定后续小候选池路由、简化流程或搜索策略实验。
