# Qwen2.5-7B + Flash：30 轮实验

2026-09-21：用户明确授权多轮运行，并确认“不算租卡成本”。此文件是本轮协议；旧 v0.5 文档记录的是先前待选 middle 阶段。

- 本地：固定 Qwen2.5-7B-Instruct-AWQ 快照；API：DeepSeek Flash，非思考模式。middle 接口保留在代码和旧配置中，本轮没有 middle 或 Pro。
- 开发 70 题、校准 280 题，沿用已冻结划分；30 轮，每轮 2 个动态分配的搜索/部署块；每轮保存检查点。
- 先做独立两轮短测，验证真实调用、反馈、暂停恢复；短测不作为正式学习状态继续使用。
- 正式阶段结束于 `round_0030.json`，保存 `trained_state.json`；不自动追加轮数，不用 500 题测试成绩决定是否继续。终评另行明确启动。
- 初始化有 6 个工作流：两个相同提示的单模型控制，加四个多节点模板。语义特征为工作流 18 维、路由 29 维；模型顺序固定，避免 JSON 键顺序影响恢复。
- 本轮主要成本目标是外部 API 支出。本地货币费率明确为 0，单列本地调用耗时。这是已有算力场景的 API 支出优化，不声称零能耗、零租金账单或最低总体运营成本。
- 使用原定成本奖励 `1/(1+C/C0)`，`C0=0.002777777777777778` 美元；不因成本口径改变而事后调参。纯本地工作流在该成本维度都得到 1，其时间差异不进入此目标。
- API 按实际返回的输入、缓存输入、输出 tokens 与冻结美元费率计算；生成工作流、开发评价和校准执行的 API 费用全部计入总支出。候选自身的每题执行成本不包含生成它的一次性搜索费用，两项应分开解释。
- 本地推理时间是调用耗时之和，不是电表读数或整台服务器运行时间；加载、空闲、CPU 编码时间不计入局部推理时间。服务器真实租金若由用户支付，仍存在，但按用户指示不进入算法成本目标。
- 30 轮学习 API 硬上限为 63 美元，时间硬上限 64 小时；这是停止边界，不是预计花费或必然运行时间。短测最多另占 2 美元 API，日志单列。
- 路由仍为双头 OFUL/UCB 和 Chebyshev 选择；保留探索；不根据旧六轮结果强制倾向某个模型。父生态位反馈、固定成本分箱、语义表示、逐块调度保留。

## 费用在框架中的位置

1. 调用后端：`main_models.py` 将 Flash 返回用量变成美元费用；本地记录秒数及 0 美元目标成本。
2. 账本与硬限制：`main_budget.py` 在调用前预留最坏成本，累计实际费用；不因本地费用为 0 取消调用数和时间上限。
3. 工作流评价：`MainPolicy.total_reference_usd` 加总某次工作流所有节点费用；开发集评价取每题平均。它影响成本分箱和档案入选；当前代理模型预测质量，并不直接预测美元成本。
4. 路由：以正确率和转换后的低成本奖励分别更新两头，按固定权重做选择。
5. 顶层分配：质量—成本的档案/部署 HV 及其变化进入工程曲率诊断和调度反馈；这是间接作用，不是每次简单选择最便宜模型。生成器费用也占用全局预算。

新旧实验的模型角色、语义表示、数据量和成本目标存在差异；不可把所有差异归因为学习轮数。工程诊断不代表源方案的理论保证已经验证。
