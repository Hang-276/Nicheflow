### 2.2 真正更新哪些参数

| 组成部分 | 本轮结构 | 更新方式与数据 |
|---|---|---|
| 本地 Qwen | 冻结的 AWQ 4-bit 因果语言模型 | 仅推理；调用 `eval()` 和 `inference_mode()`，没有本轮权重微调。 |
| DeepSeek | 远程聊天补全接口 | 发起推理请求；本项目不更新服务端模型权重。 |
| 工作流代理 | 输入 8 维、隐藏 8 维 tanh、输出 1 维 sigmoid | 使用已评价工作流的开发集平均正确率训练。 |
| 路由器 | 每个工作流臂两个独立的 11 维岭回归头 | 部署校准题执行后更新质量头和成本奖励头。 |
| 元调度器 | Search、Deploy 各一个 4 维岭回归头 | 操作块完成后更新对应头。 |
| 非神经状态 | 档案、分位边界、搜索统计量、曲率窗口、增长臂集、舍入余量 | 依据已完成的真实评价和反馈更新。 |

代理共有 **81 个可训练标量**：`8×8 + 8 + 8 + 1`。每个路由臂的两个头分别存储 `11×11` 的矩阵 `V` 和 11 维向量 `b`；系数由求解 `Vθ=b` 得到，不是另一个大语言模型。元调度器的每个头存储 `4×4` 的 `V` 和 4 维 `b`。[E06] [E07] [E10] [E12] [E15]

**【补充 D01】**“训练”在本轮指 CPU 代理与在线决策状态的学习，以及工作流集合的演化；不能写成“微调了 Qwen/DeepSeek”。`trained_state.json` 按代码保存的是这些状态，不是 Qwen 权重。[E05] [E06]

### 3.2 冻结解码及有效请求差别

| 项目 | 本地调用 | DeepSeek 本轮实际请求 |
|---|---|---|
| 默认温度 | 0.7，采样开启 | `temperature=0.7` |
| `top_p` | 0.8 | **不发送** |
| 最大新增输出 | 2048；若上下文余量更小则受余量限制 | `max_tokens=2048` |
| 基础解码种子 | 73129，并按调用位置派生实际种子 | 不发送 `seed` |

| `reasoning_effort` | 不适用 | 配置虽保存 `high`，但本轮非思考分支**不发送该字段** |

工作流节点若具有非空 `temperature`，执行器使用该节点温度覆盖默认值；允许范围为 `[0,2]`。候选生成提示也允许输出这一字段。因此，0.7 是冻结的**默认温度**，不是任意未来生成节点都不可改变的温度。截至截点的两份有效生成候选，其节点温度均为 `null`，继承默认值。[E08] [E09] [E15] [E16]

实际种子规则是：工作流节点以 `[execution_id, node_id, 73129]` 的规范 JSON 摘要前 8 个十六进制字符转换为整数，再对 `2^31` 取模；候选生成使用 `[attempt_id, 73129]` 同样派生。API 日志可保存请求意图中的种子，但 `provider_seed_supported=false`，不能把它解释为 API 已接受固定种子。[E09] [E15] [E26]

**【补充 D03】**本轮只固定本地采样种子的生成规则，不保证 GPU 推理位级确定性，也不保证 DeepSeek 重新请求得到相同文本。前后测若存在相同槽位和相同节点 ID，会派生相同的本地种子；工作流、提示或服务端随机采样仍可能不同。

## 4 工作流表示与初始化

### 4.1 DAG 与节点执行

工作流表示为有向无环图，节点记录 `id`、`operator`、`prompt`、`inputs`、`model`，并可记录温度和子组等字段。图记录输出节点、父代版本和拓扑原语；整个定义的规范 JSON SHA-256 作为不可变版本标识。[E08] [E26]

父代列表也参与版本摘要，所以这里的“不同工作流”精确指不同的完整图定义版本；即使节点和连边相同，父代记录不同也可能得到不同版本。这不是图同构或语义等价去重。[E08]

| 本轮允许算子 | 执行方式 | 依赖约束 |
|---|---|---|
| `Generate` | 真实模型调用 | 允许零个或多个输入节点 |
| `Format` | **真实模型调用** | 允许零个或多个输入节点 |
| `Review&Revise` | 真实模型调用 | 恰好一个输入节点 |
| `Ensemble` | 真实模型调用 | 至少两个输入节点 |
| `Identity` | 确定性复制 | 恰好一个输入节点，`model=null` |
| `Join` | 将上游输出组织成 JSON | 至少两个输入节点，`model=null` |

所有模型算子必须指定 `local` 或 `strong`；`Format` 不能填 `model=null`。`Programmer`、`Code`、`Test` 虽在通用实现中有定义，**不在本轮允许列表中**，本轮没有执行代码沙箱或测试程序。[E02] [E08] [E09]

每份图最多 12 个节点，拒绝环、重复 ID、悬空依赖以及不贡献于最终输出的死节点。节点按拓扑顺序**串行执行**，独立分支不代表并行发起推理。每次模型调用只收到公共任务对象、该节点提示和其直接依赖节点的输出。[E08] [E09]

**【范围缩减 D04】**相对于 3.4 所继承的代码和多任务工作流范围，本轮只开放上述文本数学子集。  
**【差异 D05】**相对于继承材料中的 CFG 约束采样描述，本轮候选由 LLM 先生成 JSON，再做图校验；没有对 LLM 的逐 token 输出实施文法约束。校验通过也不保证运行时一定成功。允许的变异意图包括替换节点、重连边、插入或删除子图，但不是分别实现的随机变异算子库。[E08] [E09] [S33]

候选生成提示包含父图、允许算子、模型档位、结构约束和示例输出形状，**不包含父代的数值评价反馈、当前题目或标准答案**。相对于 3.3 对“根据评测反馈生成变异候选”的描述，这是本轮生成器输入的限制；质量反馈在父代选择和代理筛选阶段使用。[E08] [S33]

### 4.2 六个实际种子工作流

先构造六个有限图模板，再以策略种子 `20260920` 打乱模板顺序；`main_seeds()` 按打乱后的索引和节点位置分配模型。以下是本轮检查点中已确认的顺序，节点缩写 `G`、`R`、`E` 分别表示 Generate、Review&Revise、Ensemble，`L/S` 分别表示 local/strong。[E06] [E07] [E23]

| 序号 | 图结构与节点模型 | 拓扑标记 | 单题最多模型调用 |
|---|---|---|---:|
| 0 | `a:G(L)`，输出 a | 无；归入 Linear | 1 |
| 1 | `a:G(S)→c:R(S)` 与 `b:G(L)→d:R(L)`，再 `c,d→e:E(S)` | Subgroup；归入 Broad | 5 |
| 2 | `a:G(L)` 与 `b:G(S)`，再 `a,b→c:E(L)` | NGT-Independent；归入 Independent | 3 |
| 3 | `a:G(S)`，输出 a | 无；归入 Linear | 1 |
| 4 | `a:G(L)→b:R(S)` | 无；归入 Linear | 2 |
| 5 | `a:G(S)` 与 `b:G(L)`，再 `a,b→c:E(S)` | 无；归入 Broad | 3 |

六图的单题调用上限合计为 15；各自在全部 35 道开发题上评价，得到 **210 个初始化工作流执行槽位、525 次模型调用上限**。遇到显式长度截断时会停止该工作流后续节点，所以实际调用次数可以少于上限；本截点初始化实际完成 502 次调用。[E04] [E05] [E23]

**【补充 D06】**六个模板、模型交替规则、打乱种子、提示词以及逐个完成评价后更新状态，均是本轮的具体初始化方案。六个种子全部经过真实开发题评价，没有用虚构样本填充冷启动统计。第 0 个种子是路由低置信回退的固定工作流。

四类冻结种子提示如下；它们与公共任务对象及直接上游输出一起组成实际消息，不代表候选生成后所有提示都继续保持这四条。[E02] [E06] [E08]

| 提示类型 | 冻结英文原文 |
|---|---|
| solve | Solve the supplied task. Follow its output_contract exactly. Return your final answer clearly. |
| reason | Work through the task carefully and check the reasoning. Follow the task output_contract exactly. |
| review | Review the upstream solution, correct errors and independently verify the result. Follow the task output_contract exactly. |
| merge | Compare the independent upstream solutions and verify their claims. Produce a single final answer following the task output_contract. |

第 0、3 个单节点种子分别使用 solve、reason。分组种子和 NGT-Independent 种子的 a/b 分别使用 solve/reason，未标记的双分支种子 a/b 使用 reason/solve；复核节点使用 review，聚合节点使用 merge。[E23]

**`round_0000` 的准确含义**：六个种子的开发题评价、档案重分箱、代理训练和曲率记录都已发生；此时路由质量头、成本头和两个元调度头的更新计数均为 0。因此它是“初始化完成、六轮自适应循环尚未开始的状态”，不是“所有组件均未学习”的状态。[E23]

## 5 外层搜索与代理

### 5.1 100 个生态位的实际定义

**【一致】**档案形状为 `5×5×4=100`。每个格子维护已评价工作流 population，最多一个当前精英 elite。对照导师第 3.1.1 节。[E01] [E11]

**成本轴**：从所有已记录、互不重复的已评价工作流中，取开发题平均单题核算美元成本的 20%、40%、60%、80% 分位点；使用 NumPy 默认分位计算。`searchsorted(..., side="left")` 将边界上的相等成本分到同一侧。新记录到来后，按原评价顺序重新构建档案。相等成本不会被强行拆开，所以不保证五格实际等频，也允许空格。[E07] [E11]

**拓扑轴**：按下列优先级判断，`V` 为全部节点数、`E` 为边数、`L` 为输出节点深度，根节点深度为 1。

1. 显式 `NGT-Independent` → 编码 3，Independent。
2. `L=V` 且 `E=V−1` → 编码 0，Linear。
3. `E/V>2.5` → 编码 2，Dense。
4. `E/V<1.5` 且 `L/V≤0.67` → 编码 1，Broad。
5. 其余 → 编码 4，Hybrid。

Subgroup 没有独立的第六种拓扑类别；它是图原语标记，仍按上述规则归类。[E07]

**异构轴**：`r=强档模型调用节点数/全部节点数`。`r=0`、`0<r≤0.3`、`0.3<r≤0.7`、`r>0.7` 分别编码 0、1、2、3。分母包含 Identity、Join 等确定性节点；分子只数 `noncheap=true` 的 LLM 节点。[E06] [E11]

**【补充 D07】**3.4 沿用三轴网格；相对于 3.3 中 `L≪V` 等定性条件，本轮补足了 0.67 阈值、判定优先级、等值边界和重分箱规则。生态位编号为 `20×成本编码 + 4×拓扑编码 + 异构编码`。

### 5.2 档案准入与增长臂

空格直接接纳。若格子已有精英，候选必须同时满足质量不低、美元成本不高，而且至少一个方向严格改善，才替换当前精英。质量和成本完全相同或彼此不可比时不替换，但已评价候选仍留在 population 中。质量是开发题平均正确率，成本是平均每题核算美元成本。[E11]

**【补充 D08】**这一具体单格严格 Pareto 准入规则沿用 3.2 Algorithm 1 的工程落地方式；3.4 的搜索伪代码没有重新完整列出它。重分箱时按原顺序再次应用规则，所以不可比候选的先后顺序会影响该格保留哪个精英。[E11] [S32]

某工作流一旦作为精英加入路由臂集，后续没有删除旧臂的机制。因而路由可选集合是**历史已加入的精英工作流集合**，不一定等于某一时刻档案里的当前精英集合；历史臂也不受“最多 100 个当前精英”这一数量上限直接约束。[E07] [E12]

### 5.3 搜索选择公式及统计口径

本轮搜索使用的时钟为：

$$
t_s=1+\text{累计不同已评价工作流数}
$$

在当前分箱下，`n_i` 是落入生态位 i 的已评价工作流数量，`q̂_i` 是这些工作流开发集平均质量的算术平均。初始化和新评价后的重分箱会重新构建这组统计，而不是仅在被选父代上递增访问计数。[E07]

$$
\mathrm{UCB}_i=\hat q_i+1.0\sqrt{\frac{\log t_s}{n_i}},\qquad
\rho(t_s)=1.0\,t_s^{-0.01}
$$

清醒条件是 population 至少为 1。密度是沿三个网格坐标轴各移动一步的有效邻居中，当前被精英占据的比例；**不计中心格，不含对角邻居，边界处只计算存在的邻居**。只保留密度不超过 `ρ(t_s)` 的格子。[E07] [E11] [E13]

每次选 `k=2` 个生态位，逐步最大化：

$$
\mathrm{UCB}_i+0.1\,[\log\det K_{S\cup\{i\}}-\log\det K_S]
$$

核矩阵为：

$$
K_{ij}=\mathrm{UCB}_i\mathrm{UCB}_j
\exp\{-1.0\,\|z_i-z_j\|_2^2\}
$$

其中 `z_i` 由归一化的 3 维生态位坐标 `[b_cost/4,b_topology/4,b_hetero/3]`，加该格精英的 8 维结构特征组成。[E07] [E13]

**【一致】**选择步骤保留 3.4 的 ACSR 候选过滤、组合贪心以及 `log det(K_S)`；没有换成 `log det(I+K_S)`，也不是随机 DPP 抽样。核主子矩阵奇异或非正定会报错，不增加对角扰动。过滤后不足 2 个候选格会触发 `SpecGap`，不会自动减小 k。[E13] [E14]

**【差异 D09】**导师第 3.1.5–3.1.6 节以生态位访问计数和搜索轮次表达更新；本轮使用“不同已评价工作流数”作为时钟，并按**候选最终落入的当前格子**统计质量。虽然生成记录保存父代生态位，但 `observe()` 不将候选回报直接记到被选父代生态位。故不能称为逐字实现了原文的父代访问计数／半带反馈语义。[E07] [E30] [E13]

**【补充 D10】**六邻域、`ρ0=1`、`α=0.01`、种群阈值 1 和核带宽 1 为本轮选择。代码直接计算幂律阈值，没有额外的正数下限或另一个稳定点参数。

### 5.4 结构特征和代理训练

工作流的 8 维特征 `g(G)` 按以下顺序定义，除两个指示量外均在 1 处截顶：

| 维度 | 数值 |
|---|---|
| 1 | `min(V/12,1)` |
| 2 | `min(E/66,1)` |
| 3 | `min(L/12,1)` |
| 4 | `min(根节点数/12,1)` |
| 5 | `min(LLM 调用节点数/12,1)` |
| 6 | 是否具有 `NGT-Independent` 标记 |
| 7 | 是否具有 `Subgroup` 标记 |
| 8 | `min(所有节点 prompt 字符数之和/12000,1)` |

代理结构为：

$$
\hat q(G)=\sigma\bigl(\tanh(g(G)W_1+b_1)W_2+b_2\bigr)
$$

每次出现新的已评价工作流，用**全部累计记录**继续训练当前代理 50 步，全批量交叉熵梯度下降，学习率 0.05。标签为每个工作流在 35 道开发题上的平均质量；不是 35 个独立的代理训练样本。已有代理权重不会在每次 fit 前重新随机初始化。[E07] [E10]

两个选中父代分别产生一个候选；先剔除结构无效候选，再将合法候选按代理预测质量排序，取前 `ceil(0.5×合法候选数)` 个实际评价。因此每个搜索块最多真实评价 1 个候选；合法候选只有 1 个时，该候选仍被选中。完全相同的已评价图版本不再重复评价，生成该图已经发生的调用仍记成本。[E10] [E30]

**【补充 D11】**8→8→1 结构、50 步、学习率 0.05、筛选比例 50% 以及确定性排序都是本轮具体参数。筛选分数就是代理预测质量，没有另加旧版 3.2 代理分数中的通信密度惩罚项；本轮 ACSR 在生态位候选池过滤阶段实施。[E07] [E10] [S32]

**【差异 D12】**相对于 3.3 继承设计中的“语义嵌入空间”，本轮使用人工结构特征。特征不编码完整提示语义、答案语义或模型身份；相同结构特征可能对应不同模型或不同提示含义。搜索核、代理和 Vendi 的结果不能解释为经过语义编码器验证的语义多样性。[S33] [E07]

## 6 中层双目标路由

### 6.1 特征与两套参数

对查询 q 和工作流 a，路由特征为：

$$
\phi(q,a)=\left[1,\min\left(\frac{\mathrm{len}(q)}{2048},1\right),
\min\left(\frac{\mathrm{digits}(q)}{128},1\right),g(a)\right]\in\mathbb R^{11}
$$

`len(q)` 是 Python 字符串长度，不是 token 数；`digits(q)` 通过字符的 `isdigit()` 计数。只读取公共输入中的 `question`，不读取学科、难度、参考解答或标准答案。[E07] [E32]

**【差异 D13】**3.4 第 3.2 节要求联合上下文特征，但没有固定编码器；3.2 的继承实施方案提到轻量编码器及其训练。本轮没有训练查询语义编码器，只使用上述手工统计和结构特征。因此“符合线性上下文接口”与“完成了原设想的语义编码器”是不同的结论。[E01] [S32]

每臂质量、成本奖励两个头分别初始化 `V=I_11`、`b=0`，收到样本后：

$$
V\leftarrow V+\phi\phi^\top,\qquad b\leftarrow b+\phi r,\qquad \hat\theta=V^{-1}b
$$

采用下列实际置信半径，其中岭系数 `λ0=1`，声明噪声界 `R=1`，声明参数界 `S=2`，`δ=0.05`：

$$
\beta=R\sqrt{\max\{0,\log\det V-d\log\lambda_0+2\log(1/\delta)\}}+\sqrt{\lambda_0}S
$$

$$
\mathrm{UCB}(a)=\phi^\top\hat\theta_a+\beta_a\sqrt{\max(0,\phi^\top V_a^{-1}\phi)}
$$

预测值及 UCB 没有被裁剪到 `[0,1]`。以上 R、S 是算法输入参数，本轮没有证明真实噪声和真实系数一定满足这些界。[E12]

### 6.2 决策和成本奖励方向

**【一致】**保留每臂独立的双头岭回归、OFUL 置信宽度和 Chebyshev 决策：

$$
a_t=\arg\max_a\min\{w_q\mathrm{UCB}_q(a),w_c\mathrm{UCB}_c(a)\}
$$

权重顺序固定为 `(0.5,0.5)`、`(0.25,0.75)`、`(0.75,0.25)`，坐标依次是质量和成本奖励。校准部署按全局查询索引循环使用这三个权重；分数完全相同按现有臂的插入顺序选取。[E07] [E12]

质量奖励为当前题目的 0/1 正确性。成本奖励采用：

$$
r_c=\frac{1}{1+C/C_0},\qquad C_0=10/3600\ \text{USD}
$$

`C` 是该次工作流执行的核算成本。成本越低，成本奖励越高。若最大标量化分数严格小于 0，回退到已经评价过的第 0 个种子。新增臂只初始化新参数，旧臂参数保留。[E06] [E07] [E12]

**【补充 D14】**导师第 3.2 节把第二个目标称为 Cost，却没有唯一规定如何与“最大化 UCB”统一方向。本轮补入上述倒数变换、尺度 C0、三点权重网格和低置信阈值 0；这些数值不能归为导师指定参数。[E01] [E26]

开发集对种子和候选的批量评价用于档案、代理、搜索、曲率及相应搜索块的元反馈；**不会直接拟合路由双头**。只有校准部署反馈更新被选择臂的路由参数，终评反馈禁止更新参数。[E05] [E07] [E30]

## 7 顶层曲率与预算调度

### 7.1 曲率使用什么集合效用

本轮将工作流映射为二维点 `(q,r_c)`，两个坐标都取越大越好的方向，超体积参考点为 `(0,0)`。对一个新评价的工作流，取其重分箱后的生态位 i；S 为**当时档案里其他生态位的当前精英点**，并计算：

$$
f(i\mid\varnothing)=\mathrm{HV}(\{(q_i,r_{c,i})\}),\qquad
f(i\mid S)=\mathrm{HV}(S\cup\{(q_i,r_{c,i})\})-\mathrm{HV}(S)
$$

该点可以来自未替换该格原精英的新候选；构造 S 时排除的是候选所属格。每份观测保存候选和条件集合、成对边际与对应调用凭据。[E07]

**【补充 D15】**导师第 3.3 节写出了抽象集合效用 f 和边际比，但没有唯一确定如何把 Vendi、质量和成本构造为同一个可执行 f。本轮的“档案快照二维 HV”是对此的具体补充，**并不等于完整搜索—路由—调度过程的全局真实效用或真实总曲率**。[E01] [E26]

### 7.2 经验窗口与边界规则

窗口最多保存 32 条有效观测；有效计数 m 是窗口内工作流边际观测的条数，不是题目数。分母为零的记录不进入窗口；同一工作流 ID 或同一整组调用凭据不能通过改名重复增加有效样本数。[E07] [E17]

在主循环第 t 轮：

$$
\gamma_{\rm emp}=\max_{o\in W}\left(1-\frac{f_o(i\mid S)}{f_o(i\mid\varnothing)}\right),\qquad
\epsilon_t=\sqrt{\frac{\log(t/0.05)}{m}}
$$

实际分支如下：

| 条件 | 实际处理 |
|---|---|
| `m=0` | `gamma=1`，`fallback=true`，epsilon 不计算 |
| `epsilon>0.8` | `gamma=1`，`fallback=true` |
| 其余 | `gamma=gamma_emp+epsilon`；超过 1 时截为 1，并单独标记 `capped_at_one=true` |

计算 `h(γ)=(1−exp(−γ))/γ`，在 `γ=0` 时取极限值 1。[E17]

**【差异 D16】**导师第 3.3.3 节的证明描述依赖同一 `(i,S)` 的重复访问、有效观测及其他假设。本轮从不同新工作流及随时间变化的档案快照生成一次性比值，未实施同一 `(i,S)` 的独立重复测量；重叠开发题与条件档案也不保证统计独立。计算了 epsilon 不代表验证了导师的高概率集中结论。

**【补充 D17】**无观测回退、置信常数 1、窗口 32、阈值 0.8，以及在未触发 epsilon 回退时把 `经验值+epsilon` 截为 1，均是本轮具体规则。`fallback=false` 与 `gamma=1` 可以同时出现，不能仅根据 gamma 值判定触发了回退。

**【差异 D18】**导师第 5.2 节列出曲率估计均摊 O(1)。本实现的估计函数扫描窗口求最大值，按窗口长度计为 O(w)；新增观测的去重还会遍历历史 `seen` 记录。固定 w=32 限制了扫描规模，但不能把源码直接描述为已实现通用的均摊 O(1) 增量估计器。[E17]

### 7.3 元上下文与更新奖励

Search、Deploy 各有一个 4 维岭回归头，岭系数和 OFUL 参数与路由层相同。上下文为：

$$
x_{\rm meta}=\left[\frac{B_{\rm remain}}{B_{\rm total}},\frac{Vendi}{100},HV_{\rm deploy},\min\left(\frac{epoch}{100},1\right)\right]
$$

这里的 B 仅指 12 个自适应操作块对应的预留核算额度，**不含初始化或终评额度**；随已完成块数递减，不按真实已花美元直接递减。[E06]

Vendi 以当前档案精英的 **8 维结构特征**构造未乘 UCB 权重的 RBF 相似度矩阵，取 `exp(特征值归一化后的香农熵)`。它不同于搜索选择所用的“3 维格坐标 + 8 维结构特征 + UCB 权重”核。[E07] [E14]

部署 HV 先对每个已部署工作流累计的 `(单题质量,单题成本奖励)` 取均值，再对这些点计算二维 HV。操作块奖励为：

$$
r_{\rm Search}=\Delta Vendi/100,\qquad r_{\rm Deploy}=\Delta HV_{\rm deploy}
$$

负增量保留，不改写为零。Search 奖励并不是档案 HV 增量；该档案 HV 仅用于另一条曲率观测路径。[E07]

### 7.4 比例分配与实际执行顺序

令 Search 和 Deploy 元线性头的 UCB 分别为 `U_s`、`U_d`，实际分配公式是：

$$
s=h(\hat\gamma)\max(U_s,0),\quad d=\max(U_d,0),\quad
\beta_s=\begin{cases}s/(s+d),&s+d>0\\1/2,&s+d=0\end{cases},\quad\beta_d=1-\beta_s
$$

每轮 2 个块，舍入余量初始为 0.5。计算 `target=carry+2×beta_s`，搜索块数取 `min(2,floor(target))`，新余量为 `target−搜索块数`，剩余块全部部署；**一轮内部先执行所有搜索块，再执行所有部署块**。[E06]

**【补充 D19】**上述 UCB 比例式、特征归一化、两种增量奖励和累计余量舍入，是导师第 3.3.7 节未写出的具体分配规则。h 只直接缩放搜索侧，不同时缩放两侧，不能称该公式由导师定理唯一推出。

**【差异 D20】**导师第 2.1.2 节描述异步增长、接收反馈后调整预算；本轮主驱动同步串行，每个学习轮开始时只计算一次调度，随后执行该轮两个块。块后虽更新参数，第二个块不重新计算本轮分配；两个块使用同一轮初的元上下文进行相应更新。[E05] [E06] [E07]

### 8.2 题目呈现和标签隔离

协议名为 `math_verbatim_with_inline_asymptote_v1`。保留题面及其中 `[asy]` Asymptote 源码为原样文本，**不渲染图像、不执行源码，也不因含 Asymptote 而删除题目**。开发、校准、quick35 中分别有 3、4、7 道含内联 Asymptote 的题目。[E18] [E19] [E20]

模型输入包含 question、context、options、public_tests、attachments 和 output_contract。MATH 输出合同为 `Final answer in \boxed{...}.`。标准答案、完整参考解答、数据角色和难度等私有元数据不在该公共对象中。数据加载会检查分区角色、任务 ID、公共输入摘要和规范化题面重复。[E18] [E25] [E32]

**【补充 D22】**导师没有规定本轮采用“保留图形源码的纯文本数学协议”。本协议不能描述为多模态图像理解、附件处理或已打通 GAIA 外部工具。

### 8.3 一次运行的顺序

1. 加载冻结协议、数据和两个模型档位，建立独立调用账本。
2. 六个种子各评价 35 道开发题，每个种子结束后更新档案、代理和曲率；写入 `round_0000`。
3. 执行 6 个学习轮。每轮调度 2 个操作块，共 12 块；搜索和部署各占多少块由策略决定，不预设为各 6 块。
4. 每个搜索块最多生成 2 个候选、真实评价 1 个；评价该候选使用全部 35 道开发题。
5. 每个部署块取 8 道校准题，使用全局 query_index 按冻结顺序推进，超过 70 题时回绕复用。配置 70 题不保证本轮会全部访问，更不保证各题访问次数相同。
6. 每轮结束保存参数健康检查与该轮检查点。若六轮全部完成，保存 `round_0006` 和 `trained_state.json`。
7. 完成学习后执行一次冻结终评。主驱动不在每个学习轮结束后都执行 quick35。

**【补充 D23】**6 轮、每轮 2 块、每部署块 8 题以及校准题回绕，是本轮执行规模和采样规则。六轮不是六个独立随机种子重复试验。成功完成时应有 `round_0000` 至 `round_0006` 共 7 份检查点；截点实际只有第 0 份，不能提前写成 7 份已产出。[E05] [E23]

## 9 终评与失败样本口径

### 9.1 冻结路由的终评

终评复用学习结束的图集合和路由双头。按三组权重逐组遍历 35 道题，每题每权重只执行一个采样槽位，合计 `3×35×1=105` 个工作流执行槽位；一个槽位可包含多个模型节点调用。选择方法仍是带冻结置信宽度的 **OFUL + Chebyshev**，不是只按预测均值选臂。[E05]

执行前后检查学习状态和冻结路由状态摘要相同；终评不更新档案、代理、曲率、调度器或路由器。报告还检查完整 task×weight×sample 网格，以及终评起点之后是否出现学习更新事件。[E05] [E21]

**【补充 D24】**只有 `Pass@1`，因为每题每权重只有 1 个样本。三组权重是三个运行条件，不是同一条件的 3 次采样，不能合并称为 Pass@3。没有本轮多随机种子重复或由协议自动产出的统计显著性结论。[E02] [E14]

### 9.2 MATH 评分

从输出提取 boxed 答案，再调用固定版本 `hendrycks/math` 的 `is_equiv()`。评分器 revision 为 `940d1bf8d976b7e2afa9059a52350ffcdc880c1c`，本地文件 SHA-256 为 `c4101b1f51a2bb65665194aecd9f761d668c0c248a0350f196c2950e87488527`。[E22]

每题质量为 0 或 1；没有提取到 boxed 答案时计错并记录解析失败。这里的“正确”指该冻结评分器判定通过，不意味着使用了任意数学表达式都完备的符号证明系统。

### 9.3 长度截断和其他失败

**【补充 D25】**`length_limit_outcome=zero_quality_no_retry`。显式 `finish_reason="length"` 导致该工作流终止后续节点，质量记 0，保留已发生的成本；不重试、不扩充 token、不解析残缺答案。该样本可作为有效的失败观测进入开发平均质量、代理标签或部署反馈。[E02] [E09]

此规则只适用于显式 `length`，**不把 `length_context_limit`、API 异常或任意非 stop 结束统一降为正常零分样本**。候选图生成阶段若没有正常 stop，不形成有效候选；不是对残缺 JSON 打零分后当作一个已评价工作流。[E09]

错误答案与结构校验拒绝不等于系统执行故障。主驱动配置连续 3 条未完成有效评价的 execution 后停止；但初始化／候选评价不完整、环境问题、未知调用计费或完整性错误也可能更早阻止继续。不能简写为“任何错误都自动重试三次”。[E05] [E09] [E24]

### 9.4 各种 HV 不能混写

| 使用位置 | 构造方式 |
|---|---|
| 曲率 | 当前档案快照中各点的 HV 边际，点来自开发题均值质量及平均成本的倒数奖励 |
| 部署反馈 | 每个已部署臂的单题 `(q,r_c)` 历史均值，再算 HV |
| 终评报告 | 每组权重的平均质量，以及 `1/(1+该组平均单题成本/C0)`，再算三组条件点的 HV |

这些都以 `(0,0)` 为参考点，但数据集合与成本聚合顺序不同。一般 `mean(r_c(C))` 不等于 `r_c(mean(C))`，不能把三种 HV 当作同一个统计量。[E07] [E21]

### 10.2 质量成本比较用哪种美元

每个工作流成本为各实际模型调用成本之和：

$$
C=C_{\rm API}+C_{\rm local},\qquad
C_{\rm local}=\sum\frac{\text{本地调用实测秒数}}{3600}\times1.0\ \text{USD}
$$

本地 1 USD/GPU-hour 是**声明的核算费率**，不是已验证的租赁账单。该口径不计模型加载、空闲、CPU 调度等成本。[E15] [E21]

API 使用供应商返回的 prompt/completion/cache token 数乘冻结费率。以下仅描述本轮程序保存并使用的历史核算表，**不是对当前供应商价格的重新查询或保证**：[E02] [E15]

| 冻结时段 | 非缓存输入 USD/百万 token | 缓存命中输入 USD/百万 token | 输出 USD/百万 token |
|---|---:|---:|---:|
| peak | 0.30 | 0.006 | 1.20 |
| off_peak | 0.15 | 0.003 | 0.60 |

代码在 UTC 周一至周五的 `[01:00,04:00)`、`[06:00,10:00)` 使用 peak，其余使用 off_peak；优先根据 API 返回的 `created` 时间判断，缺少时使用调用起始时间。冻结表的保存日期为 2026-09-20。[E15]

**【补充 D27】**导师没有指定上述本地声明费率、分时表及 C0。相同预留块上限不代表实际支出相等；API 缓存、时段、生成长度和本地耗时都可能改变工作流成本与生态位归属。`actual_invoice_verified` 为 false，不能把程序核算美元写成已核验支付金额。

### 11.2 当前报告工具的已核实口径问题

以下问题属于**报告辅助代码的核验发现**，不冒充真实模型实验结果。现有离线验证以构造记录复现，本次再次检查结果一致：[E28] [E29]

3. `weight_table()` 自身核对的是 `(权重索引,父集题目位置,采样索引)` 槽位集合，没有同时核对两侧 task_id 与实际权重值相等。人工构造的同槽位、异题目／异权重数据会通过该函数；这证明校验缺口，不证明现有真实数据已配错。

这些问题不改变本文已从原始事件确认的配置与截止计数，但后续 before/after 报告不能仅凭比较脚本顺利产出就宣称逐题配对和所有统计口径均已一致。
