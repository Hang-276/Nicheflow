## 3. 最小执行计划：有上限，有退出条件

### A. 先收尾现有 v072：不新增实验分支

- 从原数据库恢复；已完成的开发、种子和节点调用全部复用。
- 保持每域 **5 轮×2 个候选槽**、每槽最多2次提议、每候选20道开发反馈题；失败/重复也消耗槽位，绝不“补到效果好”。
- 完成已规划的每域20题筛选、40题×2校准、100题×2终评，沿用现有候选与单模型矩阵。CNY150/USD5、H调用/token及会话上限不增加，额度再拒绝就暂停。
- 仅审计新增未决数学案例；已签名的历史决定复用。配对区间按题抽样，三个域主指标分别报告。
- 一次离线报告：单次 Flash、校准选出的固定模型、两档、三档、加入固定/搜索工作流、匹配调用比例随机路由。补充两种四臂池只需离线分析；当前分析器尚未包含这两组，不能称已完成完整归因。
- **退出条件：** 达到原轮次/预算后结束。若候选始终被单模型支配，停止扩大多节点搜索；若三档不优于两档，不强行让三个档位都被选中。若结果混合或区间宽，记为“不确定”，不临时追加轮次。

### B. 下一版本的必做修复：输出契约 + 停止行为

实现范围：

1. 最终格式契约由系统模板固定；变异只能改指定的求解内容，不能改输出字段和解析规则。系统提示不能保证模型百分百遵循，仍需运行后校验。
2. HotpotQA 只接受完整 JSON 或确定性移除外层代码围栏后的 JSON，校验字段类型；不从任意散文猜答案或让 LLM 修复。数学保留原始回答和版本化提取规则，不把截断正文事后改为成功。
3. 本地数学采用一个预先固定的简洁停止提示方案，仍为8192、同解码参数。先不改采样参数，不新增更长输出档。

一次验证包：

- **离线，0 API：** 回放已有问答输出，区分“合法内容被解析漏掉”和“模型没有产出契约内容”；检查正确答案不被篡改、失败被保留。覆盖新解析/提示边界的定向测试即可。
- **在线问答：** 复用已存在的20道完整反馈题，对两个已出现格式问题的固定候选各跑一次修订版；最多40份工作流回答、**60次模型调用**。不只补原先失败的题。旧版使用已保存同题回执；这是已观察开发集上的工程检查，不是新的独立效果证明。
- **在线本地数学：** 同40道开发题×2次，只跑一种新提示，**80次本地调用**；旧版80条回执复用。统计端到端质量、截断、token及调用时间，不只统计完成子集。
- **接受规则：** 解析不得凭空生成或改变答案；问答格式失败应减少且逐案排除明显新增系统性退化；本地提示只有在截断减少、端到端质量点估计不降且平均输出token不升时采用。这是小样本工程选型门槛，不作统计显著/非劣效宣称。
- **不通过：** 保留原解码设置，明确记录失败；不自动加长token或再试十种提示。最多一次针对已定位缺陷的修订复测，仍不通过则该候选退出部署池，或停止放大受影响路径。

### C. 有限升级：只在 B 后仍存在可观察失败时做

- 先实现两条规则：L失败→M独立重答；M失败→H独立重答。每题最多两次调用，不自动串成 L→M→H。
- 触发仅限 `finish_reason=length`、缺少合法最终答案/确定性格式失败。正确性未知但格式完整的错误不会触发；标准答案、隐藏测试结果不能参与。API额度/未知计费也不能当自动换模型理由。
- 上级模型只读原题；完整记录首轮成本。离线固定样例检验“已付回执不重发、最多一次升级、未知状态暂停”。
- 开发材料每域40题×2×2条路径最多480个触发机会，只对实际触发且没有同协议可复用回执的项新增调用，**新增调用硬上限30**；按预先固定哈希顺序取前30项，超出只记录未覆盖。
- 有限样本用于验证触发与恢复机制。全体题的离线回放若复用独立单模型回执，明确标为模拟级联，不宣称实测端到端延迟。30项上限不足时不估计完整策略效果，更不能把未调用项当成功。
- 若恢复率差或成本不合算，停在简单作答前路由，不把复杂升级列为论文必需模块。

### D. 节点是否帮忙：仅为准备保留的审阅方案做

- 从开发阶段预定的代码、问答各20题出发，复用同一份 L 上游输出；统一修订后的最终输出契约，比较 M 接收/不接收这份上游内容，两侧其他指令保持相同，每侧2次。
- 上限 **160次 M 调用**。报告改错→改对、改对→改错、端到端质量与完整工作流成本；不用各自随机上游的差异归因。
- 若 v072 已决定不保留此类审阅路径，本项跳过。若对照显示无收益或明显污染，移除这个模板；不继续堆审阅节点补救。
- 这只检验共享草稿的作用，不冒充所有计划/审阅机制的全面消融。

### E. 搜索开放性：实现边界明确，效果验证有条件

- 下一版本先加入结构化编辑操作、实际差异日志；模型替换、提示编辑、增加、删除/重连按允许字段校验。只统计真正发生的操作，不能用 `requested_edit` 当实际覆盖。
- 探索池保留已评估的非精英；重启从任务无关图模板/约束生成，不依赖父代。两者不能自动进入部署池，仍须通过同一评价与筛选。
- 功能检查用固定生成样例证明：可无父代生成、可选非精英、合法新结构可入档、失败不无限重试、旧精英可保留；不发模型请求。
- **只有决定在下一轮研究中保留“开放搜索”作为主要贡献时，做一次小对照；否则保留设计并暂缓实验。** 域预定为 MBPP，不能看终评后换到有利题型。
- 两种策略：纯精英；混合探索。每个搜索种子各5个槽，混合分支固定为精英3/重启1/非精英1；非精英为空时记录回退，不能虚报覆盖。2个搜索随机种子，两种策略同调用/token/费用上限、同反馈题。每个候选10道预定开发题，最多2次提议、3次执行调用；每次运行只留1个开发赢家，在同20道筛选题各评价一次。
- 总上限：20个候选槽×10题×3节点 + 40次提议 + 4个赢家×20题×3节点 = **880次模型调用**。两臂按相同费用上限停止；达到任一上限即止，不为填满槽位追加预算。此数是调用数上限，不是两臂实际花费必然相等。
- 若仅增加结构数而筛选权衡没有改善，不扩大该机制。两种子是先导，不能据此写多种子稳健结论；也不进一步展开重启/非精英四组合、更多比例与多父代重组。

## 4. 放大前的决策与停止规则

1. **必做只有 A 与 B。** A 是原定未完成实验；B 首轮最多140次新模型调用（其中80次纯本地）。C≤30、D≤160、E≤880均有明确触发条件，不默认全部执行。所有可选项都触发时，首轮新增上限1210次，不能将它当成自动获批的新费用预算。
2. 代码只跑与新增逻辑有关的定向检查；修复最多一次有明确原因的复测。每次复测沿用同一调用上限并单独计费记录，不循环直到结果好看。
3. 最终比较必须包含单次 Flash 和校准选择的固定模型。仅比“总用 Max”省钱不足以支持方法价值。优先比较质量—费用前沿；本地GPU占用、排队和延迟另报，不能因记零API费自动宣布占优。
4. 当前100题/域终评用于判断是否值得放大，不宣称证明1pp非劣效。后续大规模确认只冻结一套主要方法、一套主要对比和指标；用先导不一致率估计样本量，按题聚类，明确多域/多比较处理。
5. 如果观察 v072 终评后据此改了方法，该终评不能再用于新版本独立确认。新的确认留出集只开一次；不挑题、换主指标或反复跑到显著。
6. **放大方向随证据选择：** 搜索无增益但路由有收益，就聚焦路由；路由不胜简单固定策略，就不启动更大搜索来掩盖；三档没有增量价值，就诚实报告并缩小部署池。遇到负结果可以改变研究主张，不无限增加验证。
7. 暂缓：新一轮模型选型、27B/更多模型、全面预算/采样网格、语义特征多版本调参、代理过滤、自适应调度、多父代重组、更多外部任务。只有主方法出现明确收益或这些机制成为明确研究目标，才另立计划。
